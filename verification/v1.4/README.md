# 1.4.0 驗證與預覽程序觀察

本次只執行小量資料的單元與瀏覽器檢查。沒有啟動模擬器、沒有執行 Android 編譯／測試，也沒有執行 100 筆商品或大圖壓力測試。

## 功能檢查

- 9 組資料單元測試：v1 搬移、v2 備份、穩定攤位 ID、號碼正規化與重複、未指定攤位、照片／排序／地圖標記保留、星號型別、跨場次關聯、六種主題與 URL 驗證。
- 單一瀏覽器與 3 筆舊商品：全站捲軸隱藏、場次透明設定按鈕、新增選單、空攤位、攤位圖、名稱／號碼／連結／備註、商品攤位預選、星號與篩選、完售與復原、改名不拆散商品、暖陽黃深色文字、重開保存、格式 2 備份還原、刪除攤位保留商品。
- 3 組小量搬移檢查：寫入失敗不部分提交、重試成功且保留 v1 快照、錯誤備份不變更資料。
- 功能檢查使用正式建置的臨時靜態伺服器，結束即正常關閉，避免開發伺服器自動重載干擾結果。
- 測試中修正了刪除攤位時拖曳暫存仍引用舊攤位的畫面錯誤；現在交易後會先呈現最新商品關聯。

細節見 `unit-results.txt`、`browser-results.json`、`migration-results.json`。

## CPU 排查

- 核對預覽 PID 3024 為本專案的 Node/Vite 程序，啟動命令為 `node_modules/vite/bin/vite.js --host 127.0.0.1`，目前預覽網址為 `http://127.0.0.1:5173/`。
- 歷史 Vite 日誌確實包含 Android 測試報表變更造成的 page reload；這只能證明不必要的監看存在，不能單憑此認定持續 CPU 負載的根因。
- 將 Android、recovery、verification、dist 與測試目錄排除監看，明確關閉輪詢；Vite 因設定變更自行重啟監看服務，同一 PID 繼續提供預覽。
- 重載設定後的兩秒取樣，CPU 時間增量為 0；再一次五秒閒置取樣仍為 0，記憶體約 131.2 MiB。沒有產生額外負載或測試流量。原始數值見 `preview-cpu.json`。
- 嘗試讀取短 CPU profile 時，本機系統拒絕開啟 Node inspector 連接埠，沒有取得可定位函式的 profile。因此目前僅能確認設定重載後負載下降，無法區分監看範圍與舊程序內部狀態各自的影響。
- 保留需要的 5173 預覽；本次未另起常駐開發伺服器。功能測試的靜態伺服器及獨立瀏覽器已正常關閉。
